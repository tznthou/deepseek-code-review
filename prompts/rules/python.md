# 補充規則：Python

這次的改動含 Python 檔案。除了通用規則，以下是這類檔案特有的缺陷形狀。

## 錯誤被吞掉

- **例外被捕捉後只有 `pass`**，沒有記錄也沒有重新拋出。
- **`except` 子句抓不到實際會拋出的例外型別**——那段處理程式碼永遠不會執行。
  判斷方式：看 `try` 區塊裡呼叫的函式，它失敗時真的會拋例外嗎？如果它是回傳
  錯誤碼或只印警告，那 `except` 就是死碼。
- **子程序或 API 呼叫設了「失敗不拋出」的參數，回傳值卻沒有被檢查**。
  症狀是整條流程回報成功但實際什麼都沒做。
- **裸 `except:`** 會連 `KeyboardInterrupt` 和 `SystemExit` 一起吃掉。
- 重新拋出時遺失原始追蹤資訊；用 `raise ... from err` 保留。

## 邊界與型別

- 空容器被當成非空使用：`xs[0]`、`max()`、`min()`、切片前沒有先判斷。
- 上游可能回傳 `None`，而下游直接當成有值使用。
- 字典用 `d[k]` 取值卻沒有處理鍵不存在的情況。
- `int()` / `float()` 轉換外部輸入（環境變數、JSON 欄位、命令列參數）時沒有處理
  轉換失敗。
- 用 `is` / `is not` 比較字串或數字字面值——那依賴實作層級的駐留行為，要用 `==`。

## 可變預設值與共用狀態

- `def f(x=[])` 或 `def f(x={})`：預設值只建立一次，跨呼叫共用。
- 模組層級的可變全域變數被跨請求或跨執行緒修改。
- **不要報**：函式從頭到尾沒有修改那個參數時，可變預設值不構成缺陷。

## 資源

- 檔案、socket、鎖、連線沒有用 `with` 開啟，早期返回或例外時會外洩。
- `finally` 的清理不完整，或根本沒有 `finally`。

## 安全

先確認那個輸入真的由外部控制，再報：

- `eval` / `exec` 處理外部輸入。
- `subprocess` 帶 `shell=True` 且指令字串由外部輸入拼接。
- `pickle` 或不安全的 YAML 載入處理外部資料。
- SQL 用字串拼接或 f-string 組成，而不是參數化查詢。
- 密碼、token、個資被寫進 log。

## 不要報的

- 不要報型別註記缺失、docstring 缺失、命名風格——除非違反同一份 diff 裡的既有慣例。
- 不要報 `.pyi` 檔案裡「未使用的 import 或參數」——stub 宣告的是介面，本來就不執行。
- 不要報效能問題，除非 diff 顯示那段在迴圈裡或明確是熱路徑。
- 不要報併發問題，除非 diff 裡有證據顯示這段程式碼會被多執行緒或非同步呼叫。
- 不要報「缺少測試」——你看不到測試檔案是否存在於這次 diff 之外。
