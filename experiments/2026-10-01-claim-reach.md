# 用 grep 反駁 finding 的說法，能刷掉多少誤報（2026-10-01）

[← 實測紀錄](README.md)

## 問題

finding 裡有一類說法是「某個東西不存在／沒做」：沒檢查、沒處理、沒用到、未定義。如果 finding 自己點名了那個東西，程式可以拿 grep 去 code 裡找，找到了就能反駁，不用再問一次模型。

`v1.1.0` 加過一層「用第二次呼叫模型過濾誤報」，實測誤刪的比刪對的多，`v1.2.0` 整層移除（[README §8](../README.md#已驗證)）。換成確定性的 grep，值不值得做？這一步只量射程，不實作。

這裡的「射程」指句型屬於這一類、grep 才有機會反駁的 comment；「反駁器」是假想中那支拿 grep 去找的程式。

## 跑前定好的事

- **資料**：AACR-Bench（Apache-2.0）裡由 AI 產生、資料集標為只需要 diff 層級上下文的 comment，共 760 則。資料集附的對錯標記（說明寫是專家驗證）：558 則正確、202 則錯誤
- **分類**：只看 comment 文字，用寫死在腳本裡的英文 regex 判斷句型（這 760 則沒有中文）
  - 「不存在」型：斷言缺少、沒用到、沒檢查、沒處理、未定義、忘了……
  - 寬版：再加上「寫死」型，用來對照 09-21 的粗估（那次的腳本沒留下來，詞表無法逐條對照）
- **算什麼**：射程內錯的、對的各幾則；假設「射程內錯的全部刪掉、對的一則都不誤刪」，precision 最多升到多少
- **不在這裡定門檻**：09-21 已經看過粗估（錯的 13%、對的 18% 在射程內），看過數字再定的門檻不算數，要不要做留給看完數字再決定

## 方法

- 跑前檢查：regex 對 17 個自己寫的例句全對；子集重現 760 = 558 + 202
- 射程內的錯誤 comment 逐則讀過，判斷「如果 code 裡找得到那個東西，能不能反駁」。只看 comment 文字、沒看 code，判讀的是語言模型（Claude）
- 沒有呼叫 DeepSeek

## 結果

| 定義 | 射程內的錯誤 comment | 射程內的正確 comment | 對：錯 | precision 上限 |
|---|---|---|---|---|
| 「不存在」型 | 26/202（12.9%） | 103/558（18.5%） | 3.96：1 | 73.42% → 76.02%（+2.60pp） |
| 寬版（再加「寫死」型） | 31/202（15.3%） | 115/558（20.6%） | 3.71：1 | 73.42% → 76.54%（+3.12pp） |

- **「不存在」型跟 09-21 的粗估相近**（12.9%、18.5% 對 13%、18%）；寬版略高
- **射程內的 26 則錯誤 comment，說法點名了一個找到就能反駁的東西的，只有 7 則**，另有 3 則在邊界（要多一步才判得出來）。判讀時有 2 則附了完整建議文字的文法修正被算成碰不到，照字面其實也查得到，算進去最多 9 則。其餘的 grep 碰不到：要讀控制流程、看執行環境、判斷設計意圖或文法，或者本來就是意見；有幾則只是碰到關鍵字，說法本身不是「不存在」
- 照這個算，就算反駁器完美、射程內 103 則正確的一則都不誤刪，precision 上限也只有 **74.10%（+0.68pp）**，9 則的算法是 74.30%（+0.88pp）；邊界的也算進去是 74.40%～74.60%（+0.98～+1.18pp）。判讀沒看 code，所以這些都是上限
- 射程內正確的 comment 是錯的 4 倍。以 7 則算，反駁器只要誤刪 8 則，誤刪的就比刪對的多，正是 `v1.1.0` 那層失敗的形狀；誤刪 20 則（射程內正確的約五分之一），precision 就退回原點

另一個想法是「建議的改法已經在 code 裡，就丟掉」。窄版（改法字面上已經存在）的機制跟 grep 反駁一樣；落在「不存在」句型裡的，最多就是上面那幾則；其他附了建議文字的錯誤 comment，要看 code 才知道，這裡沒量。寬版（事情已經被處理，包括註解寫明的刻意決策）要判斷語意，想不到寫成確定性規則的辦法；用模型判斷，就回到 `v1.1.0` 失敗的那一型（單次呼叫、沒有工具）。

## 限制

- regex 抓的是句型關鍵字，有漏抓：射程外的錯誤 comment 也有同型的說法（例如「has been removed」「there is no explicit …」），漏多少沒有量。上面的上限是這組 regex 的，不是 grep 反駁的
- 「建議的改法已經在 code 裡」要看 code 才判得出來，comment 文字估不了，這裡只做了定義
- AACR 的 comment 來自多個模型；kit 用的 `deepseek-v4-pro`，誤報的組成可能不同
- 26 則錯誤 comment 的判讀只看文字、單次，是語言模型做的
