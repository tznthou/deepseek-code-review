# v1.4.0 的信心改法：行內留言有沒有漏掉更多真問題（2026-09-28）

[← 實測紀錄](README.md)

## 問題

v1.4.0 改了 rubric 裡信心值的用法：原本叫模型把信心低於 0.6 的 finding 直接省略，改成告訴它這個數字拿來做什麼——0.7 以上貼成行內留言，低於 0.7 只列在摘要表（[CHANGELOG 1.4.0](../CHANGELOG.md#140---2026-09-24)）。依據全是整檔新增的合成標的，當時寫了「看不到改善就改回來」。

這句照字面做不到。合成標的上量到的差距，是不成立的 finding 被貼成行內留言的比例從 83% 降到 71%。要有八成把握在真實 PR 上分出這個差距，新舊兩版各要約 190 筆不成立的 finding；發版後三天，本 repo 的 PR 上只收到 5 筆。而且舊版在正式環境不會再跑，拿不到對照。

所以換一個答得了的問題：**在修改型 PR 上，v1.4.0 有沒有讓行內留言那層漏掉更多功能缺陷。**

## 跑前定好的事

判準在呼叫 API 之前寫定，之後沒改。

- **兩個臂只差 rubric**：v1.4.0，對上它的前一版 `v1.3.1`
- **分母**：Qodo 的功能性缺陷 309 則，全部算，包括不在 diff 裡的
- **行內那層**：信心 ≥ 0.7 的 finding，也就是會貼成行內留言的那些
- **改回的條件，兩條都要成立**：
  1. 行內那層報到「同一個問題」的缺陷，前一版比 v1.4.0 多 10 則以上（約 3 個百分點）。只比第一輪，盲標只標第一輪
  2. 行內那層的位置命中，前一版兩輪裡低的那一輪，還是高於 v1.4.0 兩輪裡高的那一輪。這條是為了擋掉單輪的運氣
- 兩條都成立就改回，否則保留 v1.4.0

## 方法

- **資料與兩層命中的定義**：同[修改型 PR 的基準線](2026-09-25-qodo-bench.md)（Qodo PR-Review-Bench，100 個修改型 PR）
- **v1.4.0 那一臂直接用基準線的兩輪**，前一版 rubric 新跑兩輪。基準線跑完之後，review 程式、定位程式、補充規則都沒改過。四輪都是 100 個 PR 全部跑完：前一版第二輪有 1 個 PR 的輸出被長度上限截斷，照續跑的設計重跑一次就成功（怎麼處理是看結果之前定的）
- **兩臂混在同一批盲標**：前一版第一輪的全部候選配對，加上 v1.4.0 第一輪信心 ≥ 0.6 的候選配對，共 838 組，打亂後分給 9 個標記員（語言模型）。配對編號看不出來自哪一臂，標記單不含信心值、嚴重度、輪次。v1.4.0 那一臂用這批新標籤，不沿用基準線的舊標籤，所以兩臂是同一批標記員在同一時間標的
- **標記品質**：看到標記結果之前，另一個獨立的標記者（同樣是語言模型）先抽 30 組標，「是不是同一個問題」與細分類都 30/30 一致。v1.4.0 第一輪重標的 413 組，跟基準線那次的標籤比，「是不是同一個問題」有 407 組一致
- **花費**：新跑的兩輪約 $0.97（DeepSeek 離峰價）

## 結果

**保留 v1.4.0。兩個條件都沒成立。**

| 功能性缺陷 309 則 | v1.4.0 | 前一版 |
|---|---|---|
| 行內那層報到同一個問題（第一輪） | 122 | 130 |
| 行內那層的位置命中（第一輪／第二輪） | 151／149 | 160／149 |
| 信心 ≥ 0.6 那層報到同一個問題（第一輪） | 137 | 137 |
| 信心 ≥ 0.7 的 finding 數（第一輪／第二輪） | 270／278 | 294／288 |
| 沒對上標準答案的高信心 finding／PR（第一輪／第二輪） | 0.91／0.90 | 0.93／1.00 |

基準線頁的 44.3% 算的是全部信心層級，這裡的前兩列只算行內那層。

- **方向是前一版在行內那層略高，但沒過門檻**：多 8 則，門檻 10 則。同一份前一版 rubric 跑兩輪，位置命中就差 11 則（160 與 149），8 則落在單輪雜訊的量級裡。第二個條件要擋的正是這種單輪運氣
- **差別只在信心 0.6～0.7 這一帶**：信心 ≥ 0.6 那層兩版都是 137 則。v1.4.0 把一部分真問題的信心打到 0.7 以下，改列在摘要表、不貼成行內留言。信心低於 0.6 的 finding 另外抓到 5 則，也只列在摘要表（這 5 則用的是基準線那次的標籤）
- **v1.4.0 貼出的行內留言比較少**：信心 ≥ 0.7 的 finding 兩輪平均少約 6%。沒對上標準答案的高信心 finding，兩版平均只差 0.06 筆／PR，同一份前一版 rubric 跑兩輪就差 0.07，分不出來。沒對上不等於誤報：Qodo 只列注入的缺陷

## 限制

- 只量了 recall。真實 PR 上的誤報沒有量到
- 合成標的上事後注意到一個現象：把操作者自己設定的值（例如環境變數）當成外部輸入的誤報，v1.4.0 報得比較多（10 次跑有 8 次，舊版 9 次跑有 1 次）。那是從約 50 個項目裡事後挑出來的，這次沒有驗證
- 摘要表變長之後有沒有人看，沒有量
- 只比了功能性缺陷，違反 repo 規則的那類不在判準裡
- 兩臂不是同時跑的（相隔兩天多）。這段期間 API 端的模型如果有更新，會混進差距裡
- 資料集 2026-02 公開，可能被模型看過；標記員與被評的都是語言模型

## 因此改了什麼

kit 沒改，v1.4.0 保留；CHANGELOG 1.4.0 那句「看不到改善就改回來」以這頁結案。[規範那組實驗](2026-09-26-rules-loop.md)的數字建立在 v1.4.0 的 rubric 上，保留之後不用重跑。
