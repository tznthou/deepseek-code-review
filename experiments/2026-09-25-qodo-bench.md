# 修改型 PR 上抓得到幾成（2026-09-25）

[← 實測紀錄](README.md)

## 問題

kit 在「修改既有檔案」的 PR 上，抓得到幾成缺陷？

之前的評估補不上這一格：AACR-Bench 只能評「一則 comment 對不對」，量不到漏掉多少；我們自己的合成標的，三個 diff 都是整檔新增，量不到改既有 code 的情況。

## 跑前的預期

這是第一次量，目的是建基準線，沒有事先猜數字。

## 方法

- **資料集**：[Qodo PR-Review-Bench](https://huggingface.co/datasets/Qodo/PR-Review-Bench)（MIT），revision `a73957c4`。100 個修改型 PR（真實 repo 的 fork，缺陷是注入的），標準答案 580 則：309 則功能性缺陷、271 則違反 repo 規則
- **設定**：rubric 用 v1.4.0，其他參數照 CI
- **跑兩輪**，兩輪都是 100 個 PR 全部跑完
- **命中分兩層**：
  - 位置命中：finding 定位後的行號，落在標準答案的位置 ±3 行內。「位置準、機制錯」也會算進來，所以是上限
  - 同一個問題：盲標。一個改動能同時修掉兩者，才算同一個問題；同一處但講的是別的事、或指對地方卻講錯機制，算部分相關
- **盲標**：430 組候選配對分給 4 個標記員（語言模型），看不到信心值與嚴重度。在看到標記結果之前，另一個獨立的標記者（同樣是語言模型）先抽 30 組標：「是不是同一個問題」30/30 一致，細分類 29/30
- **花費**：兩輪合計 $0.98（離峰；第二輪幾乎全部吃到快取）

## 結果

| 範圍 | 則數 | 位置命中 | 同一個問題 | 含部分相關 |
|---|---|---|---|---|
| 功能性缺陷（全部） | 309 | 57.3% | **44.3%** | 55.7% |
| 功能性缺陷（diff 內定得到位置的） | 296 | 59.8% | 46.3% | 58.1% |
| 違反 repo 規則（全部，沒給它規則） | 271 | 27.3% | 10.7% | 15.5% |
| 違反 repo 規則（diff 內定得到位置的） | 265 | 27.9% | 10.9% | 15.8% |

- **功能性缺陷有一半以上沒報到「同一個問題」。** 位置對上、講的卻不是同一個問題的有 46 則——位置準、機制錯
- **違反 repo 規則的只抓到一成。** 這一輪沒給它規則，它不知道這個 repo 的慣例（給了之後的結果見[下一組實驗](2026-09-26-rules-loop.md)）
- **整體 recall 很穩**：兩輪的功能性位置命中是 57.3% 對 57.6%
- **個別 finding 很不穩**：同一個 PR 兩輪報的位置，重疊程度（Jaccard）中位數只有 0.40；第一輪的 finding 只有 61% 在第二輪的同一個位置出現
- 對上標準答案的 finding 有 84% 信心 ≥ 0.7，其他 finding 是 72%。這不是 precision：Qodo 只列注入的缺陷，沒對上的不一定是誤報

## 限制

- 缺陷是注入的，標準答案也不完整，所以只量得到 recall，量不到 precision
- 資料集 2026-02 公開，可能已經被模型看過
- 標記員跟被評的都是語言模型（Claude 標 DeepSeek），沒有人類標記當對照
- 只有兩輪，變異數還估不了

## 因此改了什麼

kit 本身沒改。這組數字成了基準線：之後改 prompt 或流程，先在同一份資料上跑一輪，拿功能性 recall 跟它比。第一個這樣做的是[把 repo 規範給它](2026-09-26-rules-loop.md)那組。
